# 首页卡片滚动稳定性设计

## 目标

修复首页横向卡片在鼠标滚轮和触控板输入下偶发不翻页、停在两张卡片之间、长滑后倒退吸附，以及低帧率时动画失稳的问题；保持现有卡片视觉、顺序、视差和整体缩放风格不变。

## 已确认根因

1. 滚轮输入乘以 `0.5` 后，`deltaY=80` 恰好得到 `40`，而旧逻辑使用严格的 `< -40` / `> 40`，因此临界输入不会翻页。
2. 动画帧通过当前位置修改 `activeIdx`，而滚动限制和最终吸附又读取同一个变量，导致展示状态反向影响导航状态。
3. 弹簧使用可变步长显式积分，允许 `dt=50ms`；相同参数在约 `36ms` 起数值发散。
4. 宠胖胖精灵动画在卡片不可见时仍持续请求动画帧，且首屏同时解码 idle 与 wave 两张大图；背景粒子持续以显示器帧率绘制 520 个粒子。
5. 小幅滚动期间整张卡片持续禁用点击，且小地图使用不可聚焦的 `div role=button`。

## 方案比较

### A. 仅调整阈值

把严格比较改成包含等号并降低阈值。改动最小，但无法消除 `activeIdx` 状态耦合、惯性输入多次吸附和掉帧时的弹簧失稳，因此不采用。

### B. 独立手势控制器与稳定弹簧（采用）

新增无 DOM 依赖的 `scroll-core.js`，负责输入归一化、单手势单翻页和固定子步长弹簧。`scroll.js` 只负责 DOM、计时器和视觉更新；已确认卡片索引与预览索引分离。该方案保留现有视觉，能用 Node 内置测试覆盖关键边界。

### C. 改为浏览器原生 CSS Scroll Snap

稳定性高、无自定义积分，但需要改写当前居中缩放、视差和卡片容器结构，交互手感变化明显，超出本次修复范围，因此不采用。

## 交互规则

- 垂直或水平滚轮均可驱动卡片，取绝对值更大的轴，避免斜向输入被重复相加。
- 同一手势累计有效位移达到 `40px` 时立即提交相邻一张卡片；等于阈值也算提交。
- 一次手势最多翻一张，提交后的惯性尾部输入只延长手势结束计时，不继续翻页。
- 未达到阈值的输入只做有限跟手预览，静默 `160ms` 后回到已确认卡片。
- `activeIdx` 只在明确提交、点击小地图、键盘或触摸结束时改变；动画过程不得修改它。
- 触摸拖动使用触摸开始时的已确认卡片作为固定原点，纵向触摸不拦截。
- 页面隐藏时取消未完成手势并精确吸附到已确认卡片，恢复时重置帧时间。
- 用户启用“减少动态效果”时直接落到目标状态，不运行弹簧。

## 数值与性能规则

- 弹簧按最多 `1/120s` 的固定子步积分，单次累计时间最多处理 `100ms`，避免低帧率发散。
- 卡片点击在平移动画结束时恢复，不等待较慢的缩放弹簧。
- 宠胖胖仅在画布进入视口且页面可见时运行；wave 精灵图首次悬停时再加载。
- 背景粒子限制为约 `30FPS`，页面隐藏时取消动画帧，显示后再恢复。

## 可访问性

- 小地图使用原生 `button type="button"`，保留 `aria-label`。
- 提供清晰的键盘焦点样式；左右方向键继续翻页。
- 核心平移与缩放尊重 `prefers-reduced-motion`。

## 验收标准

- 单次 `deltaY=80` 能从第 1 张稳定翻到第 2 张。
- `deltaY=79` 不翻页并回到第 1 张。
- 一串连续大滚轮事件最多前进一张，最终精确落在卡片中心。
- 指示器不会在吸附过程中跳到另一张后再倒退。
- 弹簧在连续 `50ms` 帧间隔下保持有限并收敛。
- 页面隐藏/恢复后无中间态，卡片可继续滚动和点击。
- 首次加载不请求 `wave.webp`；宠胖胖离开视口后停止绘制。
- 小地图按钮可通过 Tab 聚焦并用 Enter/Space 激活。
